# scripts 打包发布速查

本目录的脚本均在仓库根目录使用 PowerShell 7（`pwsh`）执行，产物只写入 `dist/` 下对应环境子目录。

| 目标 | 脚本 |
| --- | --- |
| 构建并发布后端 Docker 镜像到 COS | `scripts/publish-cos-release.ps1` |
| 打包应用服务器目录 | `scripts/package-server-bundle.ps1` |
| 打包数据库服务器目录 | `scripts/package-database-bundle.ps1` |

前置条件：`pwsh`、Docker（构建镜像时）、`coscli`（上传 COS 时）、服务器端 `sha256sum`。

## 1. 安装与配置 COSCLI

### 1.1 开发机（Windows）

1. 从[腾讯云 COS 工具页](https://intl.cloud.tencent.com/zh/document/product/436/43265?lang=zh)下载 Windows 版 `coscli-windows-amd64.exe`，重命名为 `coscli.exe` 并加入 `PATH`。
2. 初始化独立配置文件，避免与默认配置混用：

```powershell
New-Item -ItemType Directory -Force "$HOME/.config/cees" | Out-Null
New-Item -ItemType File -Force "$HOME/.config/cees/cos-release.yaml" | Out-Null
coscli config init --disable-log
```

交互配置填写：

```text
配置文件路径：C:\Users\<用户名>\.config\cees\cos-release.yaml
Secret ID / Secret Key：cees-release-bot 发布子用户凭据
Session Token：留空
Bucket Name：cees-ai-1403013862
Bucket Endpoint：cos.ap-chengdu.myqcloud.com
Bucket Alias：cees-release
```

### 1.2 应用服务器（Linux AMD64）

```bash
curl -fL https://cosbrowser.cloud.tencent.com/software/coscli/coscli-linux-amd64 -o /tmp/coscli
install -m 0755 /tmp/coscli /usr/local/bin/coscli
coscli --version
coscli config init --disable-log
chmod 600 "$HOME/.cos.yaml"
```

服务器重新初始化，配置相同 Bucket、Endpoint 和 Alias `cees-release`。配置文件含密钥，不得提交 Git，也不要复制或截图 `coscli config show` 输出。

## 2. 打包 database-bundle

```powershell
pwsh ./scripts/package-database-bundle.ps1 -Environment staging
pwsh ./scripts/package-database-bundle.ps1 -Environment production
```

- 环境文件优先用 `infra/database/.env.<environment>`，缺失时回退到 example。
- 默认不含 Docker 镜像；数据库服务器无法访问镜像仓库时加 `-IncludeImages`，把离线镜像写入包内。
- 产物：`dist/database-bundles/<staging|production>/cees-ai-db-<environment>-<timestamp>-<git-sha>.tar.gz(.sha256)`。
- 常用参数：`-EnvironmentFile <path>`、`-OutputDirectory <path>`、`-KeepExpandedDirectory`。

## 3. 打包 server-bundle

```powershell
pwsh ./scripts/package-server-bundle.ps1 -Environment staging
pwsh ./scripts/package-server-bundle.ps1 -Environment production
```

- 环境文件优先用 `.env.<environment>`，模型配置优先用 `models.<environment>.toml`，缺失时回退到 example。
- 产物：`dist/server-bundles/<staging|production>/cees-ai-<environment>-server-<timestamp>-<git-sha>.tar.gz(.sha256)`。
- 常用参数：`-EnvironmentFile <path>`、`-ModelConfigFile <path>`、`-OutputDirectory <path>`、`-KeepExpandedDirectory`。
- 包内含真实 `.env` / 模型配置时属于 Secret 文件，须走受控通道传输；`bundle-manifest.json` 会标记 `template`（仍含 `change_me`）或 `ready`。

## 4. 打包并发布后端服务

发布脚本构建 API 与 ai-service 镜像，导出为单压缩包并上传到 COS `releases/<staging|production>/<release-id>/`，最后更新 `latest.json`。

Staging：

```powershell
pwsh ./scripts/publish-cos-release.ps1 `
  -Environment staging `
  -UseChinaImageMirror `
  -CosAlias cees-release `
  -CosConfigPath "$HOME/.config/cees/cos-release.yaml"`
  -AllowDirty
```

Production：必须工作区干净，且使用已在 Staging 验证通过的同一 `release-id`：

```powershell
pwsh ./scripts/publish-cos-release.ps1 `
  -Environment production `
  -ReleaseId <staging-release-id> `
  -UseChinaImageMirror `
  -CosAlias cees-release `
  -CosConfigPath "$HOME/.config/cees/cos-release.yaml"
```

- 本地产物：`dist/releases/<staging|production>/<release-id>/`。
- `-UseChinaImageMirror` 仅切换基础镜像来源，不配置代理、不改 lockfile；显式传入 `-NodeBaseImage` / `-PythonBaseImage` / `-UvBaseImage` 时以显式值为准。
- Staging 存在未提交修改时可加 `-AllowDirty`；Production 始终要求干净工作区。
- 本地试跑不上传加 `-SkipUpload`；其他参数见脚本头部注释（`-Platform`、`-NoCompression`、`-UpdateLatest` 等）。

## 5. 推荐发布顺序

1. 打包并部署 database-bundle（先启动数据库）。
2. `publish-cos-release.ps1` 构建并发布后端镜像。
3. 打包 server-bundle 上传到应用服务器，执行 `infra/deploy-cos-release.sh` 拉取并导入镜像、跑迁移后启动服务。

详细部署步骤与安全要求见 `infra/README.md`、`infra/database/README.md` 和 `infra/tencent-cos/README.md`。
