# 财务报销与支出数据设计

> 状态：已实现
> Owner：C
> 契约：`packages/contracts/openapi/openapi.yaml`
> Prisma migration：`0033_c_finance_expense_fullstack`

## 1. 范围

本期财务域提供租户级报销类别、报销草稿、费用明细、附件、提交撤回、审批、付款确认、状态历史和只读统计。NestJS API 是正式财务事实唯一写入方；Desktop 只通过版本化 API 操作数据。

本期不实现总账、会计凭证、应收应付、税务申报、固定资产、工资核算和银行直连。

## 2. 状态机

```text
DRAFT -> SUBMITTED -> APPROVED -> PAID
                    -> REJECTED -> DRAFT
        -> WITHDRAWN -> DRAFT
DRAFT/REJECTED/WITHDRAWN -> CANCELLED
```

- 只有报销人可以修改、提交、撤回或删除自己的可编辑报销单。
- 只有 `SUBMITTED` 可以审批；拒绝必须填写意见。
- 默认禁止审批自己的报销单。
- 只有 `APPROVED` 可以确认付款。
- 审批、付款和状态历史与审计日志在同一事务内写入。

## 3. 金额与附件

- 金额使用 PostgreSQL `DECIMAL(18,2)` 和 Prisma `Decimal`。
- `totalAmount` 始终由服务端对明细金额求和，客户端不得指定正式总额。
- 一张报销单使用一个 ISO 4217 三字母币种，默认 `CNY`。
- 附件复用 `FileObject`，关联前校验文件属于当前租户、已完成上传且未删除。
- 报销类别停用后仍保留历史引用，但不能用于新建或修改明细。

## 4. 数据范围与权限

- `finance.expense.request`：创建、修改、提交和撤回本人报销单。
- `finance.expense.read`：按角色数据范围读取报销数据和统计。
- `finance.expense.approve`：在数据范围内审批，不得自审。
- `finance.expense.manage_all`：管理类别、租户级查看、取消和付款确认。
- 非 `manage_all` 查询通过 `DataScopeResolverService` 折叠为成员、部门树或项目范围。

## 5. 跨模块边界

- B 的老板经营概况只读消费待审批报销数量和金额。
- D 的项目预算只读消费项目维度 `submittedAmount`、`approvedAmount`、`paidAmount`。
- 项目和部门只作为费用归属引用；财务模块不修改项目预算或组织主数据。

## 6. 失败语义

- 非法状态转换、乐观锁冲突返回 `409`。
- 跨租户、数据范围外或已删除资源按现有 API 规范返回 `403` 或 `404`。
- 明细为空、金额非法、币种非法、附件或关联资源无效返回 `400`。
- 类别已被历史明细引用时不允许删除，应改为停用。

## 7. 审计事件

类别创建、修改、删除，以及报销创建、修改、删除、提交、撤回、取消、审批和付款均写审计。元数据包含报销人、单号、状态、金额、币种、项目、审批结论和原因等必要字段。

## 8. Desktop 页面

- `/finance` 提供我的报销、审批中心、付款管理、类别管理、全部报销和财务报表。
- 列表支持关键字、状态、报销人、部门、项目、费用类别和费用发生日期筛选。
- 付款管理同时展示待付款和已付款历史，详情展示付款时间、方式和流水号。
- 财务报表展示本月费用分类，并按项目输出已提交、已批准和已付款支出。
- 报销草稿支持上传和移除票据附件，正式保存时整体替换附件关联。
