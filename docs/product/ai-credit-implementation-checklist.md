## 一、本次讨论定调

1. **两层换算均可配置**：上游 token → 计费 token 的 **token 倍率**（初始 1:1；2 倍即 1 上游 token 记 2 计费 token；输入/输出分开字段）；计费 token → credit 的**比例**（初始 1:1，同样输入/输出分开字段）；两层独立配置；
2. **档位可配置多个**：初始**基础版、高级版**两档；每档可配置功能集、每订阅单位基础额度（倍率）、**档位价格与单位单价**（订阅总价 = 档位价格 + 单位单价 × 单位数）；
3. **配置化重点**：功能（能力）是原子配置项，档位 = 能力开关的组合，费率表 = 能力 × 模型组 × 计量单位的换算——**新增功能只需"注册能力 + 挂到档位 + 配费率"，不发版不改代码**；
4. **角色与两套界面**：超级管理员（平台运营方，开发方的人）可看/可配一切配置；企业管理员只管理本企业、无任何配置权限——所有可配置项（能力/档位/费率/倍率/折扣/加油包档位等）只在**超级管理员后台**维护；
5. **复用现有权限体系，不新写一套**：档位功能集通过"档位权限码（集合码，展开为功能权限码集合）"桥接到现有 RBAC，企业订阅档位即获得企业级天花板；**档位码可配置，跟随档位功能集变动自动更新**；成员授权逻辑不变；能力 code 与现有权限码映射可配；校验两段式：① 企业档位功能集 ② 成员 RBAC 权限。

## 二、配置模型：功能如何灵活配置进档位

三层配置，全部由超级管理员后台维护、可版本化：

1. **能力目录（Capability Catalog）**：平台级枚举所有可计费能力，每项一个 code（如 `chat`、`rag`、`image-gen`、`doc-gen`、`workflow`）。**新增功能 = 注册一条目录项**；
2. **档位（Tier）**：可配置任意多档；每档 = 功能集开关（capability → 开/关）+ 每订阅单位基础额度 + 档位价格与单位单价（月/半年/年）。新增能力后只需在档位后台勾选，对应档位用户即可使用；
3. **费率表（Rate Card）**：用量 → credit 的换算配置，按"能力 × 模型组 × 计量单位（token 输入/输出、次）"配置倍率；**带版本号，调价不追溯历史账目**。

要点：

- **功能与计费解耦**：能力开关回答"能不能用"（与 AI 权限配合），费率表回答"怎么折算"，两者独立配置；
- 档位功能集、基础额度、费率全部配置化——新增功能不要求发版（配置发布即可）；
- **所有可配置项归属超级管理员后台**（能力/档位/费率/倍率/折扣/加油包档位）；企业管理员界面只有本企业的管理操作（购买/限额/报表），无任何配置入口；
- 未配置费率的调用一律拒绝（已定，防计费漏洞）。

| A4 | 订阅模型 | 档位 × 订阅单位 × 订阅持续时间（1 月/半年/一年）的购买记录与到期作废；续费时长叠加（新时长从旧订阅结束后开始）；订单表预留支付字段（渠道/状态），支付系统后续接入 | 单测：到期作废、剩余额度不补偿；到期前续费时长叠加 |
| A5 | 调用结算链路 | 调用前余额检查 + 调用后按实际用量（usage）折算 credit → **原子扣减 + requestId 幂等**（防超扣、防重复扣，硬规则）；最小单位 0.1 credit，输入输出合计后一次四舍五入；流式：结束按最终 usage 一次结算，池耗尽立即中断、已产生 token 照实计费；usage 缺失按方案 A 估算兜底 + 标记 | 并发测试：余额不为负；同一 requestId 重复提交只扣一次；取整正确；中断结算正确 |
| A6 | 池耗尽拦截 | 余额不足拒绝调用（不赊账），提示"企业 AI 额度已用尽，请联系管理员"（不含数字） | 集成测试：耗尽后调用被拒且提示正确 |
