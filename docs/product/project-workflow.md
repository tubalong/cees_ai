# 项目工作流：决策、看板、日报、里程碑与费用

> 状态：已落地
> 契约版本：`0.37.0`
> 主要实现：`apps/api/src/project-workflow`、`apps/desktop/src/features/projects`
> Prisma migration：`20260921090000_project_workflow`

## 1. 定位

项目详情页采用完整展开的项目导航，不把模块折叠到“更多”：

`概览｜项目工作台｜决策｜看板｜日报｜里程碑｜成员｜文件｜费用｜项目仓库（条件显示）｜设置`

项目工作台固定绑定当前项目且对话仅本人可见；决策、任务、日报、里程碑、费用和项目仓库继续由各自业务域作为正式事实源。

## 2. 项目工作台

- 会话新增 `contextType = GENERAL | PROJECT` 与可选 `projectId`；
- 项目会话必须由当前项目成员创建，列表查询按项目和上下文过滤；
- 项目会话在后续访问和发起轮次时继续校验项目成员关系；
- 模型上下文注入项目名称、状态、当前用户项目角色和任务/决策/里程碑/仓库/项目知识库摘要；
- 项目会话的知识库检索只允许项目归属的知识库，不允许跨项目拼接 RAG 范围；
- 对话正文保持私有，不进入项目动态；只有正式资源写入才产生动态。

## 3. 决策

决策状态：`DRAFT -> PUBLISHED -> SUPERSEDED`。

- 项目成员可以创建决策草稿；
- 草稿创建人或项目负责人/经理可以修改、删除草稿；
- 只有项目负责人/经理可以发布；
- 发布必须填写最终结论；
- 任务通过 `relationType = PROJECT_DECISION` 与 `relationId` 追溯来源决策。

## 4. 里程碑

里程碑状态：`PLANNED -> IN_PROGRESS -> ACCEPTANCE -> COMPLETED`，另有 `CANCELLED` 和人工重新打开。

- 里程碑由项目负责人/经理创建、修改和流转；
- 目标、负责人、验收标准、关联任务和关联决策由人工维护；
- 完成度根据必关联任务的 `DONE` 数量自动计算；
- 健康状态由系统计算为 `NORMAL / AT_RISK / OVERDUE`；
- 任务全部完成不会自动完成里程碑，仍需负责人进入验收并确认完成。

## 5. 日报与任务联动

- 任务进入 `DONE` 后，系统将任务标题带入任务负责人当天日报草的“已完成事项”；
- 任务负责人日报不存在时创建草稿；不存在时会自动选择项目负责人或其他有效项目成员作为审核人，找不到时保留待补充审核人；
- 日报已提交或已通过时不静默改写，只写入“日报待补充”项目动态；
- 成员可以在项目日报中修改、删除自动带入项，也可以补充计划、阻塞和备注；
- 日报提交/撤回继续复用既有 WorkReport 状态机、权限和审计。

## 6. 项目费用

项目“费用”页复用 Finance 报销域，不在项目模块复制费用数据：

- 支持手动创建项目报销、多条费用明细和发票/凭证附件；
- 保存草稿与提交财务是两个动作，提交后进入财务审批中心；
- 项目页展示已申请、已批准、已付款支出和报销状态；
- 权限继续使用 `finance.expense.request`、`finance.expense.read` 和财务数据范围。

## 7. 项目仓库

- 设置页保存仓库 URL 后才显示“项目仓库”Tab；
- 支持 GitHub、GitLab、Gitee 和通用 HTTP(S) 仓库地址；
- URL 禁止包含用户名、密码或 Token；
- 支持配置多个仓库，每个仓库独立编辑、启用和解除绑定；
- 本期只登记仓库与默认分支，不实现代码托管平台同步，也不伪造提交或 PR 数据。

## 8. 权限

| 能力 | 读取 | 写入 |
| --- | --- | --- |
| 项目工作流 | `project.read` + 项目成员 | 按资源动作校验项目角色 |
| 决策草稿 | `project.read` + 项目成员 | 作者或项目负责人/经理；发布仅负责人/经理 |
| 里程碑 | `project.read` + 项目成员 | `project.update` + 负责人/经理 |
| 项目仓库 | `project.read` + 项目成员 | `project.update` + 负责人/经理 |
| 日报 | `work_report.read` | `work_report.*` + 当前项目关联 |
| 费用 | `finance.expense.read` | `finance.expense.request` + 当前项目范围 |

跨租户、非项目成员和无权限资源统一按不存在或 403 处理；所有正式写入写审计，项目级正式事件写 `project_activity_events`。

## 9. 数据模型

- `project_decisions`：决策问题、背景、建议、最终结论、风险、后续动作、参与人和发布信息；
- `project_milestones`：目标、目标日期、负责人、验收标准、验收说明和生命周期时间；
- `project_milestone_tasks` / `project_milestone_decisions`：里程碑与正式资源的关联；
- `project_repositories`：项目仓库 URL、提供方、默认分支和启停状态；
- `project_activity_events`：项目正式动态，不记录私有聊天正文；
- `conversations.context_type` / `project_id`：项目工作台会话上下文。

## 10. 暂缓

- 外部代码仓库真实同步、commit/PR 抓取与代码索引；
- 项目预算实体和预算审批；
- 日报提交后自动更正；
- 决策和里程碑的 AI 自动写入工具；当前由工作台生成建议，用户在正式页面确认。
